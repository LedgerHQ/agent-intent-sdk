# Release process

The repository follows the single-branch Changesets model used by
`LedgerHQ/wallet-api`. `develop` is the only long-lived branch, and version tags
are the immutable release history.

## Required repository configuration

### Repository secrets

- `GH_BOT_APP_ID`
- `GH_BOT_PRIVATE_KEY`

The GitHub App must be installed on this repository and allowed to write
contents and pull requests.

### Repository variables

- `RELEASE_RUNNER`: optional runner override; defaults to
  `public-ledgerhq-shared-medium`
- `ARTIFACTORY_PUBLISH_URL`: JFrog npm publish registry

Publishing uses JFrog OIDC; do not configure a long-lived npm token. The JFrog
`github-oidc` provider must also authorize OIDC subjects from
`LedgerHQ/agent-intent-sdk`.

## Flow

1. A push to `develop` with pending changesets updates the version pull request.
2. Merging the version pull request consumes changesets, updates the version,
   and writes `CHANGELOG.md`.
3. The resulting push to `develop` has no pending changesets, so the same
   workflow verifies and publishes the package, then creates a tag and GitHub
   release.

The package tag format generated by Changesets is
`@ledgerhq/agent-intent-sdk@<version>`.

## Recovery

- If the version pull request has no CI run, verify the GitHub App credentials;
  pull requests created by `GITHUB_TOKEN` do not trigger workflows.
- If publishing partially succeeds, rerun the workflow. Changesets skips a
  version already present in the registry.
- If the publish registry variable is absent, the workflow stops before
  publishing so it cannot accidentally target the read registry.
