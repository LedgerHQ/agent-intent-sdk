The enrollment channel host reconnects after the Trustchain relay drops it, so a reviewer who leaves the enrollment page can come back and approve while the request is unexpired. The relay closes the host once its candidate leaves; the host now reopens on the same key within the existing completion deadline, at once after the first drop, then after 1, 2 and 4 seconds, then every 5 seconds, with no limit on the number of reconnects. A socket that stayed open for at least 60 seconds before it dropped restarts that backoff. The host stops when the signed request expires (also checked against the wall clock before each reopen), when `completionTimeoutMs` elapses, on `close()`, or when a socket is lost while a completion is being authenticated or persisted. After each keepalive ping the host expects a frame back within 10 seconds; a socket that stays silent is closed and reopened like a relay drop. A candidate that does not finish the handshake within `handshakeTimeoutMs` no longer fails the host; the host reopens and waits for another candidate. After the reviewer rejects the request or refuses it on the device, the host keeps waiting until the request expires, `completionTimeoutMs` elapses, or the caller closes it. A host closed or timed out while a completion is being authenticated no longer persists that completion afterwards.
